# Инструкция пользователя — «Стройконтроль»

Система ведения исполнительной документации строительства: акты освидетельствования скрытых работ (АОСР),
материалы, документы о качестве (сертификаты, декларации, отказные письма), поставки, входной контроль,
смета/факт. Веб-приложение на Django, работает локально, данные — в PostgreSQL, файлы — в папке `media/`.

---

## 1. Установка и запуск

**Требования:** Windows, Python 3.12+, PostgreSQL (база `stroy_db`, пользователь `stroy_user` — см. `.env`),
Tesseract OCR с русским языком для распознавания сканов и LibreOffice для формирования PDF.

```bat
cd C:\Users\kkypi\Desktop\Programming\stroy_control
venv\Scripts\python.exe -m pip install -r requirements.txt
venv\Scripts\python.exe manage.py migrate
venv\Scripts\python.exe manage.py createsuperuser
venv\Scripts\python.exe manage.py runserver
```

Во втором терминале запустите worker распознавания и не закрывайте его во время работы сайта:

```bat
venv\Scripts\python.exe manage.py process_cert_uploads
```

Открыть в браузере: `http://127.0.0.1:8000/`, вход — по логину/паролю суперпользователя.

Настройки подключения к базе, `SECRET_KEY` и параметры запуска находятся в `.env` (не коммитится в Git). Для локальной разработки и прежнего адреса ngrok добавьте:

```dotenv
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1,cognitive-outlet-ultimate.ngrok-free.dev
CSRF_TRUSTED_ORIGINS=https://cognitive-outlet-ultimate.ngrok-free.dev
```

`DEBUG` по умолчанию выключен, разрешены только `localhost` и `127.0.0.1`. При смене внешнего адреса обновите обе переменные. Нестандартные пути программ задаются через `TESSERACT_CMD` и `LIBREOFFICE_PATH` в `.env`. В рабочем окружении используйте `DEBUG=False` и раздавайте `media/` через веб-сервер; `SERVE_MEDIA=True` предназначено только для временного локального запуска без отладки.

**Резервные копии.** Критичны две вещи: база PostgreSQL (дамп) и папка `media/` (сканы, сгенерированные акты). Папка `backups/` в проекте — пример ручных копий перед правками.

## 2. Роли пользователей

- **Обычный пользователь** — полный доступ: просмотр, создание и редактирование всего.
- **Только просмотр** — группа Django с названием «Только просмотр» (создаётся в админке `/admin/`, туда добавляется пользователь). Такой пользователь видит все страницы, но ни одно сохранение не пройдёт — при попытке появится сообщение «У вас доступ только на просмотр». Удобно выдать технадзору. Подключение механизма — строка `'core.readonly.ReadOnlyMiddleware'` в конце `MIDDLEWARE` в `settings.py`.
- **Админка** (`/admin/`) — стандартная Django-админка, там же создаются пользователи и группы.

## 3. Главное меню (слева вверху)

| Раздел | Что там |
|---|---|
| **Внимание** | Автосбор всех проблем: просроченные сертификаты, непроверенные загрузки, несопоставленные строки накладных, объёмы сверх сметы, полномочия подписантов. Каждая строка — ссылка на место исправления. |
| **Акты** | Список актов ОСР: фильтр по статусу и объекту, поиск, сортировка, создание нового. |
| **Поставки** | Накладные (справочник `deliveries`) и экран сопоставления строк с материалами. |
| **Журнал ВК** | Журнал входного контроля — собирается сам из накладных, сертификатов и записей контроля. Выгрузка в Excel. |
| **Объёмы** | Сравнение смета/факт по помещениям и видам работ, отклонения и решения по ним. |
| **Материалы** | Справочник материалов. |
| **Сертификаты** | Справочник документов о качестве + загрузка и распознавание новых. |
| **Справочники** | Все остальные: объекты, разделы, виды работ, помещения, сметные строки, контрагенты, СРО, участники, нормативы, документы, входной контроль, замеры, решения по отклонениям, синонимы, журнал событий. |

### Пространство объекта

В шапке есть переключатель объектов. Выбранный объект запоминается в сессии: корень `/` открывает его
обзор, а разделы «Внимание», «Акты», «Поставки», «Журнал ВК» и «Объёмы» показывают данные только этого
объекта. Список объектов — `/sites/`; карточка реквизитов — «Карточка объекта» на странице обзора.

Страница обзора `/sites/<id>/` показывает реквизиты, счётчики актов по статусам, свободные замеры и
несопоставленные строки накладных, а также быстрые действия: «Новый акт», «Создать акт из замеров»
(пока заглушка) и «Загрузить сертификаты». Справочники разделов, видов работ, помещений и накладных
в формах ограничены выбранным объектом; глобальные справочники (контрагенты, участники, нормативы,
материалы) остаются общими. Старые адреса разделов перенаправляют в пространство выбранного объекта.

Вкладки **«Материалы»** и **«Сертификаты»** объекта (`/sites/<id>/materials/`, `/sites/<id>/certificates/`)
показывают материалы из накладных этого объекта и сертификаты, относящиеся к этим материалам, плюс
документы, загруженные в пространстве объекта. Копии записей не создаются: справочники материалов и
сертификатов остаются глобальными, со страниц объекта есть быстрый переход к ним. Сертификат по-прежнему
относится к материалу, а не к объекту; загрузка из пространства объекта запоминает объект происхождения.

## 4. Типовой порядок работы

1. Заполнить справочники: **контрагенты** (застройщик, генподрядчик, проектировщик, поставщики, производители), **СРО**, **участники** (ФИО, должность, приказ/доверенность, срок полномочий), **нормативы** (ГОСТ/СП).
2. Создать **объект** (помещения, разделы документации, виды работ) и в карточке объекта указать **подписантов по умолчанию**.
3. Завести **материалы**.
4. Оформлять **поставки** (накладные и позиции), сопоставить строки с материалами.
5. Загружать **документы о качестве** (сканы) или вводить по номеру; проверить в реестре; привязать к материалам.
6. Вносить **замеры/объёмы работ** (справочник «Объёмы»).
7. Формировать **акты ОСР**, проверять предупреждения, скачивать Excel, подписывать, при необходимости прикреплять исправленный файл и переводить статус.
8. Раз в неделю смотреть «**Внимание**» и прогонять проверку реестра (команда `registry_check`).

## 5. Справочники: общие правила

Все списки устроены одинаково:

- **Поиск** — ищет по всем текстовым полям записи и связанных (например, в накладных ищет и по названиям материалов в позициях).
- **Фильтры** — выпадающие списки над таблицей (по объекту, статусу, производителю и т.д.).
- **Сортировка** — клик по заголовку колонки, повторный клик меняет направление (▲/▼).
- **Добавление** — кнопка «Добавить»; рядом со многими полями есть **«+»**, открывающий форму новой записи в отдельном окне — после сохранения родительская форма сама подхватит новый вариант в списке.
- **Даты** вводятся текстом в формате `дд.мм.гггг` (принимается также `дд.мм.гг` и `гггг-мм-дд`).
- **Удаление и архив.** Удалить запись можно только если на неё никто не ссылается; иначе система сообщит, где она используется, и предложит перевести в **архив** (статус «В архиве» — архивные записи не мешают в новых документах, но остаются в старых).

Состав справочников (раздел «Справочники» → группы):

- **Объект:** объекты, разделы документации, виды работ, помещения, сметные строки.
- **Организации и люди:** контрагенты, СРО, участники.
- **Материалы и сертификаты:** нормативы, материалы, сертификаты (с привязкой к материалам прямо в карточке), документы (файлы).
- **Поставки:** накладные (позиции редактируются строками внутри карточки), входной контроль.
- **Работы:** объёмы работ (замеры), решения по отклонениям.
- **Служебное:** синонимы материалов, журнал событий.

Загрузка файла с тем же содержимым (по хешу SHA-256) блокируется — дубликат не создастся.

## 6. Объекты и подписанты

**Карточка объекта** (Справочники → Объекты → запись): название, адрес, застройщик, генподрядчик, проектировщик, договор подряда, реквизиты проектной документации (по умолчанию для всех актов), даты строительства.

**Шапка акта** — организации (застройщик, генподрядчик, проектировщик), их ИНН/ОГРН, адреса, СРО и реквизиты проектной документации. При создании акта эти данные **фиксируются снимком** в акте. Последующие изменения карточки объекта **не меняют уже созданные акты**: шапку конкретного акта можно поправить в свёрнутом блоке «Шапка акта — обычно не меняется» на странице акта, а кнопка «Вернуть как у объекта» собирает её заново из карточки.

**Подписанты объекта** — таблица в той же карточке: кто и в какой роли подписывает акты этого объекта. При создании акта эти люди **копируются** в акт (снимок). Важно: последующие изменения списка подписантов объекта **не меняют уже созданные акты** — в старом акте правьте состав вручную.

Роли в акте: представитель застройщика/заказчика, застройщика по стройконтролю, лица осуществляющего строительство, подрядчика по стройконтролю, проектировщика (ГАП), исполнителя работ, иной представитель. Одна роль — один человек: дубли роли при сохранении предупреждаются.

## 7. Поставки

**Накладная** (Поставки или Справочники → Накладные): номер, дата, объект, поставщик, кто принял, статус приёмки, отметка о паспорте качества, примечание, скан-файл. Позиции накладной — строки внутри карточки: «как написано в накладной», количество, ед. изм., номер партии.

**Сопоставление строк с материалами** (Поставки → Сопоставление, либо ссылка из «Внимания»):

- Система сопоставляет в три этапа: (1) точное совпадение с **синонимом** — сразу «подтверждено»; (2) похожее название — «автоматически опознано» (нужна проверка человеком); (3) не найдено — выбираете материал вручную.
- Кнопка **«Подобрать автоматически»** запускает пункт 2 по всем несопоставленным строкам.
- При ручном выборе есть флажок **«запомнить написание»** — строка «Лист ГКЛ Кнауф 12,5» запомнится как синоним и в следующий раз сопоставится сама. Запомненные синонимы видны в Справочники → Синонимы материалов.
- **Ввод строк текстом:** внизу страницы можно вставить строки из Excel в формате `название; количество; ед. изм.` (разделитель — точка с запятой или табуляция) — они добавятся в выбранную накладную и сразу автосопоставятся.

По умолчанию показываются несопоставленные и непроверенные строки; переключатель «показать все».

## 8. Документы о качестве (сертификаты, декларации, отказные письма)

Типы документов: сертификат соответствия, декларация о соответствии, отказное письмо, паспорт качества, информационное письмо, протокол испытаний. У сертификата и декларации **обязателен срок действия** — без него запись не сохранится.

### Загрузка сканов (Сертификаты → Загрузить)

1. Выберите один или несколько файлов (PDF, JPG, PNG, TIFF, до 50 МБ каждый). Можно сразу привязать к конкретному материалу. Если загрузка открыта из пространства объекта (`/sites/<id>/certificates/upload/`), объект запоминается как происхождение загрузки и её документы видны во вкладке «Сертификаты» этого объекта.
2. Файл встаёт в постоянную очередь в PostgreSQL и обрабатывается отдельным worker: OCR (Tesseract, локально — файл никуда не отправляется), чтение QR-кодов, проверка по реестрам. Один worker обрабатывает по одному файлу. Страница проверки сама обновляется по мере готовности; после перезапуска сайта очередь сохраняется.
3. Тот же файл (по содержимому) повторно не загружается — откроется прошлая загрузка.
4. Пока из загрузки ничего не сохранено, доступно **«Распознать заново»**.

### Проверка и сохранение (страница загрузки)

Слева скан страницы, справа карточка документа с распознанными полями: тип, номер, даты, изготовитель, продукция, страницы, ссылки реестра. Проверьте и поправьте, отметьте **«Сохранить этот документ»**, укажите материалы:

- отметьте материал из справочника (есть подсказки с пояснением, почему материал подходит: производитель, норматив, название);
- или включите **«Создать новые материалы»** и перечислите названия по строкам — материалы создадутся сами (норматив подставится из документа/реестра, если найден);
- изготовитель подставляется из справочника по ИНН/названию, либо создаётся новым контрагентом прямо из карточки.

Сохранение — только по кнопке «Сохранить»; распознанное само по себе в базу не пишется. Пока не все карточки загрузки сохранены, загрузка висит в «Внимании».

### Проверка по реестрам

- **ФГИС Росаккредитации** (сертификаты и декларации): кнопка «Проверить в реестре» в карточке. Если найден — поля заполняются данными реестра, виден статус («действует/прекращён/приостановлен»). Если номер дал несколько вариантов — выберите из списка.
- **Реестр Мосстройсертификации** — для номеров вида `RU.МСС....`.
- Сайт реестра отвечает только с российских IP; если он недоступен, проверка сообщит об этом и не сломает остальное.
- У сохранённого сертификата (Сертификаты → запись → «Проверить в реестре») можно перепроверить статус позже; расхождения с базой будут перечислены.

### Ввод по номеру без скана

На странице загрузки есть поле «номер из реестра»: введите номер сертификата/декларации — документ будет создан по данным реестра (с датами и изготовителем), можно сразу привязать к материалу.

### Регулярная перепроверка

Команда `venv\Scripts\python.exe manage.py registry_check` перепроверяет все действующие сертификаты и декларации и пишет расхождения. Удобно повесить в Планировщик заданий Windows на еженедельный запуск. Отдельный документ: `... registry_check "РОСС RU С-RU...."`, по ссылке `--url`, сырой ответ реестра — `--raw` (в `registry_debug.json`, пригодится, если реестр изменил сайт и поля перестали заполняться).

## 9. Акты ОСР

### Создание

Акты → «Новый акт»: обязательны только раздел документации и дата (дата предзаполнена сегодняшней). Номер можно не вводить — подставится следующий по разделу. При создании из карточки объекта копируются подписанты по умолчанию. Акт можно заполнять постепенно, черновиком.

### Карточка акта (всё на одной странице)

- **Реквизиты:** номер, дата, раздел, разрешённые последующие работы (из справочника видов работ или свободным текстом), число экземпляров, статус (Черновик → На подписании → На печати → Подписан / Отклонён).
- **Шапка акта** — свёрнутый вверху блок «Шапка акта — обычно не меняется». В нём видны зафиксированные при создании организации, ИНН/ОГРН, адреса, СРО и реквизиты проектной документации. Кнопка «Изменить для этого акта» открывает поля; правки сохраняются только в этот акт и не затрагивают карточку объекта и другие акты. «Вернуть как у объекта» собирает шапку заново из текущей карточки.
- **Замеры (объёмы работ):** вид работ (только из раздела акта), место выполнения (оси, отметка), кто выполнял, даты начала/окончания, объём, ед. изм. Кнопка «убрать» у строки **отвязывает замер от акта, но не удаляет его** — свободные замеры раздела можно подцепить обратно галочками внизу. Удалить сам замер можно только в справочнике «Объёмы».
- **Материалы:** либо позиция поставки (выбор из накладных этого объекта, сгруппированы по категориям; по умолчанию предлагается последняя поставка не позже начала работ), либо материал без накладной. Обязательно укажите «списано в акт» — объём.
- **Подписанты:** люди и роли. Проверяются: дубли ролей, истёкшие полномочия на дату акта.
- **Приложения:** файлы (схемы, исполнительные схемы и пр.) — выбор из справочника документов.

У выпадающих списков есть «+» для создания записи в отдельном окне — после сохранения варианты в открытых списках обновятся сами (кнопка «Обновить списки» перестраховывает).

### Предупреждения

Вверху карточки — предупреждения: что не заполнено, поставка позже начала работ, позиция не сопоставлена с материалом, роль указана дважды, полномочия подписанта истекли, у материала нет действующего документа о качестве и т.п. Excel при этом всё равно формируется — недостающее видно в файле (пустые места и строки «⚠ …»).

**Проблемы с документами о качестве не блокируют выпуск.** Если у материала акта нет действующего на дату поставки/начала работ сертификата, декларации или другого документа, либо он прекращён/приостановлен в реестре, либо распознан автоматически и не проверен, — при скачивании Excel всё равно формируется, а пользователю показывается предупреждение. В файле напротив такого материала стоит строка «⚠ …». Исправить можно позже в разделе «Сертификаты» и сформировать акт заново.

### Предпросмотр

Кнопка «Предпросмотр» показывает акт как он будет в Excel: сначала точный вариант (настоящий Excel → PDF → картинки страниц, кэшируется по содержимому формы), при недоступности Excel на сервере — HTML-вариант с теми же подстановками. Работает и с несохранённой формой (POST-состояние), в базу ничего не пишется.

### Excel

Кнопка «Сформировать Excel» — готовый АОСР по шаблону `core/templates_xlsx/Шаблон_АОСР.xlsx`: шапка с организациями и СРО, описание работ, нормативы, даты, материалы с реквизитами документов о качестве, перечень приложений, блок подписей. Если материалов много и в акт они не помещаются — в файле появится «указаны в приложении к акту» (само приложение формируйте отдельно).

### Исправленный файл

После печати и ручной правки акт можно прикрепить обратно к карточке (Excel, Word, PDF, JPG/PNG, до 20 МБ) — хранится для истории и скачивания. Автоматически сформированный Excel он **не заменяет**.

### Копирование и удаление

- **«Создать на основе этого»** — новый акт с теми же реквизитами, подписантами и приложениями (номер и дата — новые). Работы и материалы не копируются.
- **Удаление** — подписанты, материалы и приложения акта удаляются, замеры отвязываются и остаются свободными, файл исправленного акта стирается с диска.

## 10. «Внимание»

Единая точка контроля. Группы проверок (все с прямыми ссылками):

1. **Акты: проблемы с документами о качестве** (предупреждение) — у материалов неподписанных актов нет действующего документа о качестве (или он требует проверки). Выпуск Excel не блокируется: в файле такие места отмечены «⚠».
2. **Сертификаты** (ошибка) — истёкшие (с привязкой к материалам), заканчивающиеся в течение 30 дней, прекращённые/приостановленные/не найденные в реестре.
3. **Непроверенные загрузки сертификатов** (предупреждение) — загруженные файлы, из которых не всё сохранено.
4. **Накладные** (предупреждение) — строки без материала и автоматически сопоставленные, но не проверенные.
5. **Объёмы сверх сметы без решения** (предупреждение).
6. **Полномочия подписантов** (предупреждение) — истекают в течение 30 дней или истекли.

Рекомендуется начинать рабочий день с этого экрана. Сломанная проверка не роняет страницу — она покажется отдельной строкой.

## 11. Журнал входного контроля

Журнал **не хранится отдельно**, а собирается из накладных, привязанных сертификатов и записей входного контроля — поэтому всегда актуален. Фильтры: объект, период поставки, поставщик, только проблемные позиции (нет сертификата / документ не действовал на дату поставки / позиция не сопоставлена), текстовый поиск. Кнопка «Выгрузить Excel» — готовый журнал для печати. Записи входного контроля (дата, кто проверил, результат, допуск) вносятся в справочнике «Входной контроль» или открываются по ссылке из строки.

---

## 12. Объёмы: смета / факт / отклонения

Экран «Объёмы» сравнивает сметные объёмы (справочник «Сметные строки»: помещение + вид работ + объём) с фактом (сумма замеров по тому же помещению и виду работ). Для каждой строки: смета, факт, отклонение в %, допустимое отклонение (задаётся у вида работ), флаг превышения и последнее решение.

Если отклонение больше допустимого и решения нет — строка попадает в «Внимание». Кнопка «Решение» ведёт в справочник «Решения по отклонениям» с предзаполненными сметной строкой, величиной и датой. Решения имеют статусы: На подписании / Согласовано / Отклонено.

## 13. Журнал событий

Справочники → Журнал событий: кто, когда и что сделал (сохранения, выгрузки, формирование Excel, загрузка сертификатов и т.д.). Фильтры по пользователю и действию. Служит для разбора «кто менял».

## 14. Служебные команды и скрипты

| Команда/скрипт | Назначение |
|---|---|
| `manage.py cleanup_media --dry-run` | Показать, что будет удалено из `media/`: кэш предпросмотра, сгенерированные акты старше 30 дней, файлы-сироты без записи в базе. Без `--dry-run` — удалить. Порог: `--days 7`. Безопасно: всё нужное пересоздаётся из базы. |
| `manage.py registry_check` | Перепроверка всех действующих сертификатов/деклараций по реестру (см. раздел 8). |
| `manage.py process_cert_uploads` | Постоянный worker очереди OCR. Запускать отдельным процессом вместе с сайтом. Для одной задачи: `--once`; интервал опроса: `--poll-interval 2`. |

## 15. Типовые вопросы и ответы

**Excel сформировался, но напротив материала стоит «⚠ нет сертификата».**
У материала нет действующего на дату поставки (или начала работ, если поставки нет) документа о качестве. Выпуск файла это не блокирует — предупреждение показано и в карточке акта. Откройте материал (Материалы → запись), привяжите сертификат со сроком, покрывающим дату, убедитесь, что он не отклонён и, если распознан автоматически, — подтверждён, затем скачайте акт заново.

**Сертификат есть, но «не действовал на дату поставки».**
Срок документа не покрывает дату поставки/начала работ — либо поставка раньше выдачи, либо позже окончания. Нужен другой документ на тот период (или исправление даты, если она введена неверно).

**«Позиция не сопоставлена с материалом».**
Строка накладной не привязана к материалу справочника. Исправляется на экране «Поставки → Сопоставление»; включите «запомнить написание», чтобы больше не повторялось.

**Загрузка сертификата висит в «Внимании».**
Из файла не все карточки сохранены — откройте загрузку, проверьте и сохраните (или снимите флажки «Сохранить» там, где документ не нужен; карточки без флажка не мешают).

**Распознавание недоступно / Tesseract.**
На странице загрузки сертификатов строка состояния покажет причину: не установлен pytesseract, не найдена программа Tesseract или нет русского языка. Ставится установщиком UB Mannheim с отметкой «Russian»; нестандартный путь задаётся переменной `TESSERACT_CMD` в `.env`. Если очередь не движется, проверьте, что запущен `manage.py process_cert_uploads`.

**«Реестр недоступен».**
Сайт pub.fsa.gov.ru отвечает только с IP России и иногда лежит. Остальная проверка документа работает; вернитесь к проверке позже или вручную на сайте реестра.

**Дубли файлов.**
Повторная загрузка того же файла (по хешу) не создаёт копию — откроется существующая загрузка/запись.

**Нельзя удалить запись справочника.**
На неё ссылаются другие записи (защита целостности). Переведите запись в статус «В архиве» — она перестанет предлагаться в новых документах.

**Поменял подписанта у объекта, а в старых актах остался старый.**
Так задумано: подписанты копируются в акт при создании. Меняйте состав в карточке каждого акта.

**Поменял реквизиты объекта, а в старых актах прежние организации.**
Так задумано: шапка акта фиксируется снимком при создании. Откройте акт, разверните блок «Шапка акта — обычно не меняется» и нажмите «Вернуть как у объекта» (или поправьте только этот акт через «Изменить для этого акта»).

**Номер акта.**
Если оставить поле пустым, номер подставится автоматически (максимальный по разделу + 1). Можно вписать свой.

**Материалов много — в акте написано «указаны в приложении».**
В бланк АОСР помещается ограниченное число строк. Реестр к АОСР с полным списком документов формируется отдельно.

**Предпросмотр и сгенерированные файлы занимают место.**
Кэш предпросмотра и старые Excel живут в `media/generated_acts/`, чистятся командой `cleanup_media`.

**Как дать доступ технадзору «посмотреть».**
Админка → Пользователи → создать пользователя; Группы → «Только просмотр» → добавить в группу; в `settings.py` убедиться, что в `MIDDLEWARE` последней стоит `'core.readonly.ReadOnlyMiddleware'`.

**Доступ извне (ngrok).**
Добавьте адрес ngrok в `ALLOWED_HOSTS`, а его HTTPS-адрес — в `CSRF_TRUSTED_ORIGINS` в `.env`, как показано в разделе 1. По умолчанию внешние адреса не разрешены.

**Где лежат файлы и как бэкапиться.**
Сканы и документы — `media/`, вся структура — база PostgreSQL. Бэкап = дамп базы + копия `media/`.
